# Product implementation plan

This plan turns the eight UI references in `mock-images/` into a feature-backed web application. The images describe the desired product surface and visual style; they are not screenshots of current behavior, and their example values, labels, and conclusions are not trusted telemetry.

The accepted architectural boundary is recorded in [architecture decision 0061](architecture.md#decision-0061-deliver-the-mock-product-through-evidence-backed-web-capabilities). Preserve the existing Python telemetry/storage/analysis services, protected local API, and Next.js web app. Build the workflows first, then migrate the main interface to the reference layouts. Keep the current diagnostic application usable during the transition.

## Delivered slices

- **Draft region authoring:** an explicitly selected Time Trial or Practice/Qualifying attempt can produce a bounded, loader-compatible draft model. The model remains diagnostic, is not installed, and carries its source and quality warnings. See [decision 0062](architecture.md#decision-0062-author-draft-distance-region-models-from-a-selected-attempt).
- **Stage 1, first increment:** `/` remains the diagnostic dashboard and `/recordings` now hosts the existing recording, replay, capture catalog, import and job-status workflow. Shared navigation preserves allowlisted run/session/attempt/reference/model/window state, including repeated observation selections. Import and retry forms return to their originating screen through the `dashboard`/`recordings` enum; a posted URL is never treated as a redirect destination. The recordings route loads only the catalog, current recording and explicitly requested import job. Navigation does not stop local recording or replay, and their pollers clean up when the route unmounts. Query length and repetition are bounded while values are copied; if selected state cannot be carried intact, an explicit blocked-transfer marker disables screen navigation instead of allowing a latest-record fallback. Successful job navigation clears an old import error. Dashboard, Recordings and Sessions are now live navigation destinations; the other screen mockups remain planned.
- **Stage 1, second increment:** `/sessions` now hosts the bounded imported-run archive, capture/lifecycle summaries, paginated session/attempt inventory, and the all-car observation browser. A run, observation session, and car slot are requested only from explicit identities; missing or malformed identities never select a replacement. Archive pagination and observation controls stay on the selected screen and retain safe shared query state. Dashboard comparison evidence and Recording inbox links open `/sessions`; legacy dashboard `run_id` and archive-pagination links continue to render the shared panel when explicitly requested. The Sessions route does not call lap comparison, reference-selection, or engineer-query services. Filters, export/archive actions, and Sessions mock parity remain planned; see Decision 0061 for the boundary.
- **Stage 10, first increment:** `/engineer` summarizes one explicitly selected recorded attempt through the existing deterministic `attempt_summary` service. The screen displays the returned identity, capture/run/session provenance, `metadata_only` verification scope, bounded facts, qualifications, and omissions. Dashboard and Sessions link directly to this screen; malformed, missing, ambiguous, or blocked selections never fall back to a latest attempt. Regional explanations remain on the diagnostic Dashboard and return there with their exact selection. This is recorded-evidence inspection, not free-text AI, strategy, advice, or coaching admission; see Decisions 0049, 0052, and 0061.
- **Stage 5, first increment:** `/live` presents the existing player telemetry, Car Status, and lap-timing monitors for one explicitly selected UDP recording or diagnostic replay. The page pins to the selected operation ID, polls only its source, and stops rather than attaching to a replacement operation. Server-reported per-group ages remain authoritative; monitor values are hidden after request failure and cleared when the operation ends. Active Recording and Replay controls link to their pinned source. The page is inspection-only and adds no forecasts, charts, packet families, or HUD behavior; see Decisions 0015, 0044–0046, and 0061.
- **Stage 6, first increment:** `/compare` loads a bounded imported-run page, one selected run's session page, and a bounded attempt-metadata page for the explicitly selected session. Exact metadata lookups keep selected attempts available across pages without loading every attempt; off-session and unavailable identities never receive substitutes. A target, policy, manual reference or Time Trial session-best choice, and optional numeric distance window stay pinned in the URL. Existing reference and comparison services are called only for that exact pair; returned target, reference, policy scope, and requested window identities are checked before showing results. The screen reuses the linked distance charts and reports validity, lifecycle, capture counters, official timing and unsupported spans. Missing, repeated, stale, Race, unknown, or policy-mismatched selections never fall back; see Decision 0061.
- **Stage 7, first increment:** `/track` inspects one exact imported attempt using the bounded run/session attempt inventory, its observed trajectory preview, and an explicitly selected catalog model revision for standalone region observations. Run, session, attempt, path, model, and region identities are checked before evidence is displayed or spatially linked; stale and mismatched selections never receive substitutes. Attempt links from Sessions preserve their exact source. Recorded paths remain observed traces, while model regions remain diagnostic windows; Race/unknown modes can show the path and report region unavailability. No geometry activation, paired analysis, ranking, or coaching is added; see Decision 0061.
- **Stage 2, first increment:** `/settings` adds browser-local read-aloud rate and volume with atomic Apply, Cancel, and Reset; explicit local voice discovery and a fixed synthetic preview; and clear planned/unavailable states for settings that have no implementation. Applied values affect recorded-evidence speech on Dashboard and Engineer. A single bounded versioned preference record stays in browser storage and cannot change evidence or coaching authority; see Decision 0063.

## Web adaptations

- OS minimize/maximize/close buttons become browser navigation and page-level controls; no fake window chrome.
- Arbitrary Windows device names become actual browser-default/discovered device capabilities. Input mappings are limited to browser focus or explicitly available adapters; global game-focus input needs a separate native companion decision.
- “Enable In-Game Overlay” becomes “Open Browser HUD” with position, opacity, text-size and theme options for that page/popout. A transparent always-on-top overlay over the game is outside this web plan.
- “Open Folder” becomes a managed artifact catalog with upload/download. Database and recording roots stay server-configured; the browser cannot browse arbitrary server paths.
- UDP capture has no game video. Replay video requires an explicit user-selected source and measured/declared synchronization; otherwise use telemetry/path playback and label media unsynchronized. A scrubber requires seek reconstruction; single-packet Step is not a video-frame seek.
- Storage UI reports measured managed usage and a configured budget or verified disk capacity. Never display a made-up quota such as the mock's “200 GB”.
- Model recommendations are based on supported local runtime/hardware facts, not a hard-coded “recommended” model.
- Browser voice/device/filesystem features show actual capabilities and permissions, including unavailable states; they do not imply desktop-level access.

## Deferred expansions

Native packaging and window controls, automatic game-video capture, global device input, transparent always-on-top overlay, named opponent identity, unrestricted Race references/comparison, ideal racing-line inference, and universal real-2026 validation are separate architecture/evidence decisions. The mock's strategy, tyre and natural-language features remain planned capabilities, but do not bypass their data-quality and validation gates.
