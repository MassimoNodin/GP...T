# Product implementation plan

This plan turns the eight UI references in `mock-images/` into a feature-backed web application. The images describe the desired product surface and visual style; they are not screenshots of current behavior, and their example values, labels, and conclusions are not trusted telemetry.

The accepted architectural boundary is recorded in [architecture decision 0061](architecture.md#decision-0061-deliver-the-mock-product-through-evidence-backed-web-capabilities). Preserve the existing Python telemetry/storage/analysis services, protected local API, and Next.js web app. Build the workflows first, then migrate the main interface to the reference layouts. Keep the current diagnostic application usable during the transition.

## Delivered slices

Live Telemetry uses the mock composition with fresh pinned-operation data and speed/pedal/gear observation lanes. Track Analysis and Lap Comparison render arbitrary supplied shapes, named distance regions, supported timing classifications and aligned masked traces; linked cursor, channel selection, region windows and zoom use original samples. Both pages also accept bounded browser-local JSON input. Unsupported live fields remain unavailable, and observed paths retain their geometry qualifications. See [Decision 0089 and the input contract](dynamic-ui-analysis.md). Full eight-screen parity and running-stream acceptance remain pending.

API and CLI resolution use the same immutable snapshot; ordinary lap comparison accepts packaged/reviewed models while local drafts remain diagnostic. The validator reports structural and fingerprint scope only and does not verify geometry. Synthetic positive integration uses the production loader with a test-local bundle; no real model is shipped or implied physically verified. See Decision 0065.

- **Draft region authoring:** an explicitly selected Time Trial or Practice/Qualifying attempt can produce a bounded, loader-compatible draft model. The model remains diagnostic, is not installed, and carries its source and quality warnings. See [decision 0062](architecture.md#decision-0062-author-draft-distance-region-models-from-a-selected-attempt).
- **Stage 1, first increment:** `/` remains the diagnostic dashboard and `/recordings` now hosts the existing recording, replay, capture catalog, import and job-status workflow. Shared navigation preserves allowlisted run/session/attempt/reference/model/window state, including repeated observation selections. Import and retry forms return to their originating screen through the `dashboard`/`recordings` enum; a posted URL is never treated as a redirect destination. The recordings route loads only the catalog, current recording and explicitly requested import job. Navigation does not stop local recording or replay, and their pollers clean up when the route unmounts. Query length and repetition are bounded while values are copied; if selected state cannot be carried intact, an explicit blocked-transfer marker disables screen navigation instead of allowing a latest-record fallback. Successful job navigation clears an old import error. Dashboard, Recordings and Sessions are now live navigation destinations; the other screen mockups remain planned.

Dashboard comparison evidence and Recording inbox links open `/sessions`; legacy dashboard `run_id` and archive-pagination links continue to render the shared panel when explicitly requested. The Sessions route does not call lap comparison, reference-selection, or engineer-query services. Filters, export/archive actions, and Sessions mock parity remain planned; see Decision 0061 for the boundary.

See Decision 0074.

## Web adaptations

- OS minimize/maximize/close buttons become browser navigation and page-level controls; no fake window chrome.
- Arbitrary Windows device names become actual browser-default/discovered device capabilities. Input mappings are limited to browser focus or explicitly available adapters; global game-focus input needs a separate native companion decision.
- “Enable In-Game Overlay” becomes “Open Browser HUD” with position, opacity, text-size and theme options for that page/popout. A transparent always-on-top overlay over the game is outside this web plan.
- “Open Folder” becomes a managed artifact catalog with upload/download. Database and recording roots stay server-configured; the browser cannot browse arbitrary server paths.
- UDP capture has no game video. Replay video requires an explicit user-selected source and measured/declared synchronization; otherwise use telemetry/path playback and label media unsynchronized. A scrubber requires seek reconstruction; single-packet Step is not a video-frame seek.
- Storage UI reports measured managed usage and a configured budget or verified disk capacity. Never display a made-up quota such as the mock's “200 GB”.
- Model recommendations are based on supported local runtime/hardware facts, not a hard-coded “recommended” model.
- Browser voice/device/filesystem features show actual capabilities and permissions, including unavailable states; they do not imply desktop-level access.
